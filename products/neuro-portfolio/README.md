# Нейро-Портфолио

Генератор сайтов-портфолио. На входе — один файл с данными клиента, на
выходе — папка со статическим сайтом, которую можно залить на любой хостинг.
Ни сборщиков, ни базы, ни внешних запросов у готовой страницы.

```bash
python generate.py schema/example.json dist/
```

Нужен Python 3.11+ и Jinja2 (`pip install jinja2`). Больше ничего.

---

## Сборка нового клиента за 30 минут

1. **Заведите папку клиента.** Скопируйте `schema/example.json` в
   `clients/название/client.json`, рядом создайте папку `img/`.
2. **Сложите картинки** в `img/`: логотип, фото для первого экрана, по
   скриншоту или фотографии на каждый кейс. Пути в JSON указываются
   относительно самого JSON — `"image": "img/case-1.jpg"`.
3. **Заполните JSON** по разделам ниже. Поля со звёздочкой обязательны,
   остальные можно удалить: блок без данных просто не отрисуется.
4. **Выберите тему** в `meta.theme`: `theme-a`, `theme-b`, `theme-c` или
   `theme-d`. Что это за темы — в разделе «Темы».
5. **Соберите:**
   ```bash
   python generate.py clients/название/client.json clients/название/dist/
   ```
   Сборщик напечатает вес страницы и замечания: слишком длинный ответ в FAQ,
   ненайденная картинка, расхождение разметки с текстом.
6. **Проверьте глазами.** Откройте `dist/index.html` в браузере, пролистайте
   на телефоне, раскройте пару вопросов.
7. **Отдайте клиенту** папку `dist/` целиком — её содержимое кладётся в
   корень сайта.

Не уверены в теме — соберите все четыре и покажите заказчику:

```bash
python generate.py clients/название/client.json preview/ --all-themes
```

## Что заполнять в JSON

| Раздел | Обязательно | Что туда писать |
| --- | --- | --- |
| `meta` | `title`, `description`, `theme` | Заголовок вкладки (до 70 символов) и описание для выдачи (до 200). `domain` — адрес сайта, нужен для превью в соцсетях |
| `brand` | `name`, `tagline` | Название и одна строка о том, кто это и для кого. `tagline` попадает в микроразметку и в подвал |
| `hero` | `headline`, `subline`, `cta_text`, `cta_url` | Одна главная мысль и одна кнопка. `cta_url` — ссылка на переписку |
| `approach` | — | 3–4 тезиса о том, как строится работа. Коротко, без воды |
| `cases` | минимум один | Ядро страницы, разбор ниже |
| `reviews` | — | Отзывы. Пустой массив — блока нет |
| `faq` | — | Вопросы и ответы, правила ниже |
| `contacts` | хотя бы один канал | `telegram`, `phone`, `whatsapp`, `email`, плюс адрес и часы работы |
| `cta` | — | Свой заголовок и текст блока заявки. `form: false` убирает форму |
| `legal` | — | Лицо и ИНН для подвала и страницы политики |

Полный список полей с ограничениями — `schema/client.schema.json`. Поля
сверх схемы не рендерятся: сборщик о них предупредит.

### Кейс

Каждый кейс — одна история по схеме **боль → что сделали → результат →
цифры**:

```json
{
  "client": "Мария, 34 года",
  "niche": "Сложное окрашивание",
  "pain": "С чем пришли и что не получалось",
  "solution": "Что именно сделали. Конкретно, без «провели комплекс работ»",
  "result": "Что изменилось. Желательно с проверяемым фактом",
  "numbers": [{ "value": "3", "label": "визита до результата" }],
  "image": "img/case-1.jpg",
  "url": "https://ссылка-на-живой-проект",
  "quote": "Слова клиента одной фразой"
}
```

Цифр в кейсе — до четырёх, иначе карточка перегружена. Значение пишется как
есть: `+38%`, `2 дня`, `180 000 ₽`. Блок «Итог по всем проектам» собирается
сам: он считает проекты, ниши и средние по тем подписям, которые встречаются
минимум в двух кейсах. Среднее помечается знаком `≈`. Руками в этот блок
ничего не вписывается — чтобы средние появились, подписи в разных кейсах
должны совпадать дословно.

### FAQ

Ответы читает не только человек на странице, но и поисковик. Отсюда правила,
за которыми следит сборщик:

- **3–7 вопросов.** Меньше — блок не заметят, больше — размывается.
- **Ответ 40–120 слов.** Он должен быть понятен отдельно от страницы: не
  «да, конечно», а полный ответ с условиями и цифрами.
- **Без ссылок внутри ответа.** В сниппете они не кликаются, а текст ломают.
- **Пишите то, что реально спрашивают** в переписке, а не то, что удобно
  отвечать.

Google не показывает FAQ-аккордеон в выдаче с 7 мая 2026 года, но разметка
остаётся валидной и нужна для двух вещей: Яндекс блок вопросов показывает, а
нейропоиск легко цитирует короткие точные ответы.

## Темы

Различаются только набором CSS-переменных: цвета, радиусы, плотность,
шрифтовая пара. Вёрстка одна на все четыре.

| Тема | Характер | Кому подходит |
| --- | --- | --- |
| `theme-a` «Сетка» | холодная, плотная, прямые углы, тонкие рамки | техника, ремонт, автосервис, ИТ-услуги |
| `theme-b` «Воздух» | тёплая, разреженная, крупная антиква, мягкие формы | красота, здоровье, частные специалисты |
| `theme-c` «Ночь» | тёмная, песочный акцент, средняя плотность | фото и видео, студии, вечерние услуги |
| `theme-d` «Печать» | газетная полоса: линии вместо карточек, синий акцент | юристы, консультанты, образование |

Свой цвет клиента подставляется через `brand.accent_override` — например,
`"#7A2E4E"`. Цвет текста на кнопках сборщик подберёт сам по яркости.

Шрифты системные, файлов не грузим. Нужен фирменный шрифт — положите
`.woff2` в `assets/fonts/`, добавьте `@font-face` в файл темы и пропишите
имя в `--font-head` или `--font-body`. Папка `assets/` копируется в сборку
как есть, внешних запросов при этом не появляется.

## Что получается на выходе

```
dist/
├── index.html      одностраничник
├── privacy.html    политика конфиденциальности
├── style.css       вёрстка + тема + аккордеон
├── script.js       аккордеон и форма
└── img/            картинки клиента
```

Форма заявки работает без бэкенда: она собирает текст обращения и открывает
почту клиента или Telegram. Ничего никуда не отправляется, поэтому cookie и
баннера согласия на странице нет.

## Демо для клиентов

Витрина общая для продуктов студии и живёт в `products/demo/`:

```bash
python ../demo/build_site.py site/
```

Собирает три демо портфолио в разных нишах, каждое во всех четырёх темах, и
страницу вопросов и ответов продукта AI-FAQ. Сверху страницы появляется
панель с переходом между демо и переключателем тем — она существует только в
витрине: у клиента страница собирается одной темой и панели не имеет.

Витрина выкладывается на GitHub Pages через `.github/workflows/demo-pages.yml`
при изменениях в `products/` на ветке `main`. Собранная статика лежит в ветке
`gh-pages`, её и отдаёт Pages:

- салон красоты — <https://sabutorin97-boop.github.io/remix-of-ai-business-solutions/>
- автосервис — <https://sabutorin97-boop.github.io/remix-of-ai-business-solutions/garage/>

Ветку `gh-pages` руками не правят: всё меняется в `products/`, результат
приезжает туда сборкой.

Новая ниша добавляется так: кладёте JSON рядом с `../demo/beauty.json` и
дописываете строку в список `PAGES` внутри `../demo/build_site.py`.

## Проверки

```bash
python selftest.py
```

Прогоняет критерии приёмки: сборку примера, все четыре темы, поведение на
неполных и битых данных, совпадение разметки с видимым текстом, контраст,
вес и отсутствие внешних запросов.

Что проверяется руками:

- **Вёрстка на телефоне.** Откройте сборку на 320 пикселях ширины.
- **Разметка.** Скопируйте содержимое `<script type="application/ld+json">`
  в validator.schema.org и в Яндекс.Вебмастер. Тексты в разметке обязаны
  дословно совпадать с видимыми — за этим следит и сборщик, но проверка
  Вебмастера показывает картину глазами поисковика.
- **Lighthouse** в Chrome по вкладке «Инспектор». На примере выходит
  Performance 99–100 и Accessibility 100 на всех темах.

## Что внутри

| Файл | Назначение |
| --- | --- |
| `generate.py` | точка входа: данные → контекст → рендер → папка сборки |
| `validation.py` | проверка client.json и понятные сообщения об ошибках |
| `shared.py` | подключение FAQ-модуля из `products/ai-faq/` |
| `templates/` | базовая страница и блоки: hero, approach, cases, numbers, reviews, cta, footer |
| `themes/` | `base.css` — вся вёрстка, `theme-*.css` — только переменные |
| `schema/` | схема входных данных и заполненный пример |
| `assets/` | иконки контактов и скрипт формы |
| `selftest.py` | прогон критериев приёмки |

Аккордеон FAQ и разметка `FAQPage` живут в соседнем продукте
`products/ai-faq/` и переиспользуются отсюда. Второй копии вёрстки нет:
правка в модуле расходится по всем собранным сайтам.

## Чего здесь намеренно нет

Админки, CMS, базы, бэкенда, аналитики, cookie-баннера, CDN, внешних шрифтов
и иконочных библиотек. Многостраничник тоже не поддерживается: только
одностраничник и страница политики.
