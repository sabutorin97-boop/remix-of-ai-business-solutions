# Заметки по проекту

Сайт AI-студии AI-Profigrup (aiprofigrup.ru). Стек: TanStack Start, React 19,
Tailwind 4, Vite. Деплой — Timeweb Cloud Apps, есть конфиг и под Cloudflare.

Полезное для будущих сессий:

- Страницы — файловые роуты в `src/routes`. Отдельные `.html` не подхватываются,
  дерево маршрутов `src/routeTree.gen.ts` пересобирается при `bun run build`.
- Яндекс.Метрика (`src/components/site/YandexMetrika.tsx`) грузится **только
  после согласия** в баннере `CookieConsent`. Всё, что считается через Метрику,
  теряет часть аудитории. Для рекламных целей нужен серверный учёт.
- `api.telegram.org` с боевого IP Timeweb недоступен напрямую. Запросы идут
  через релей, адрес в переменной окружения `TELEGRAM_API_BASE`. **На 2026-09-08
  переменной в приложении нет**, поэтому весь исходящий Telegram молчит: и
  уведомления о заявках, и партнёрский бот. Проверка одним запросом —
  `/api/telegram/partner?secret=…&action=ping`, поле `apiHost`. Как поднять
  релей заново — раздел «Если Telegram недоступен с сервера» в `PARTNER_BOT.md`.
- Проверка перед пушем: `bun run build`. В репозитории много старых ошибок
  форматирования, поэтому `bun run lint` гоняйте по своим файлам, а не по всему
  проекту, иначе утонете в чужих правках.

## Запуск рекламы: страница /tg

Подписная страница под Яндекс.Директ и VK Ads. Файл `src/routes/tg.tsx`.
Цель — подписка на Telegram-канал `@ai_prodazhi_pro`. На этом маршруте шапка,
подвал и виджет «Спросить Макса» скрыты (условие в `src/routes/__root.tsx`).

Открытые задачи по порядку важности:

1. **Серверный переход и учёт кликов.** Кнопка ведёт напрямую в Telegram,
   поэтому часть переходов не видна: Метрика без согласия не грузится.
   Нужен свой адрес-редирект, который пишет обезличенное событие с меткой
   источника и перебрасывает в канал.
2. **Пригласительные ссылки Telegram под источники.** У канала нет параметра
   `?start=`, как у бота, поэтому прямая ссылка не даёт атрибуции. Именованные
   ссылки вида `t.me/+…` создаются в приложении, и по каждой видно число
   вступивших. Подставляются в `src/lib/telegram-channel.ts` — там все ссылки
   на канал на весь сайт, разделённые по источникам: `ads` для посадочной
   `/tg` (платный трафик) и `site` для подвала и блога (бесплатный). Пока обе
   указывают на один адрес, и в отчёте платные подписчики смешиваются с
   бесплатными.
3. **Бонус за подписку — решено и проверено вживую (2026-09-03).** Раньше тут
   было записано неверно: подарок выдаёт не бот «Азимут», а сам бот **PixSpark
   AI** (`@pixsparkbot_bot`, код в отдельном репозитории `imagegen-bot`).
   Диплинк `t.me/pixsparkbot_bot?start=bonus` (или команда `/bonus` в самом
   боте) сам проверяет подписку на канал через Telegram API
   (`bot.get_chat_member`) и один раз на пользователя выдаёт 15 генераций на
   30 дней — без участия Азимута и без ручного подтверждения. Механизм
   подтверждён вживую: в базе бота есть реальная выдача бонуса стороннему
   пользователю (не админу), и сам API-вызов перепроверен отдельно.
   На странице добавлена кнопка «Забрать бонус в PixSpark» с этим диплинком —
   **блокер на платный трафик снят**, оффер выполним.
4. **Своя картинка превью для соцсетей.** Сейчас в `tg.tsx` подставлена
   картинка с главной страницы, нужна отдельная с названием канала.
5. **Цель в Метрике.** Код шлёт цель `tg_subscribe_click`, но саму цель нужно
   создать руками в интерфейсе счётчика, иначе она не считается.

## Партнёрский бот

Кабинет партнёра в Telegram: обучение, каталог 42 ниш, скрипты, возражения и
передача клиентов в студию. Отдельного сервиса нет — вебхук живёт в этом же
приложении, роут `src/routes/api/telegram/partner.ts`. Бот —
`@AIProfigrupPartner_bot` (создан 2026-09-08, отдельный от бота заявок
`@AiProfiGrup_bot`). Инструкция по запуску и переменным — `PARTNER_BOT.md`.

- Логика — `src/lib/partner-bot.ts`, контент — `src/lib/partner-training.ts`,
  данные каталога — `src/lib/partner-catalog.ts`, партнёры в S3 —
  `src/lib/partners-store.ts`.
- Токен свой (`TELEGRAM_PARTNER_BOT_TOKEN`), но при его отсутствии бот
  поднимается на основном токене. `src/lib/telegram.ts` поэтому принимает токен
  параметром — оба бота ходят через один клиент и один релей `TELEGRAM_API_BASE`.
- **Сообщения бот забирает опросом, а не вебхуком** (`src/lib/partner-bot-polling.ts`,
  старт из `src/server.ts`). Связь с Telegram односторонняя: исходящее идёт
  через релей, входящее не доходит — 2026-09-08 вебхук вставал, но Telegram
  писал `Connection timed out` и копил `pending_update_count`, логи приложения
  оставались пустыми. Опрос выключается переменной `PARTNER_BOT_POLLING=off`,
  состояние видно в `action=ping`, поле `polling`. Вебхук-роут оставлен на
  случай, если входящий канал когда-нибудь откроется; он отвечает 503 без
  `TELEGRAM_PARTNER_WEBHOOK_SECRET`, установка — `action=set`.
- После каждого передеплоя бот молчит до полуминуты: Timeweb гасит старый
  контейнер только после того, как новый стал здоровым, обе копии опрашивают
  Telegram и получают `Conflict: terminated by other getUpdates request`. Опрос
  переживает это сам (пауза 5 секунд и повтор, прерывание запроса по SIGTERM).
  Это не поломка — проверять `polling.lastError` в `action=ping`.
- Любое сообщение без команды — разговор с наставником «Макс» через kie.ai, а
  не поиск по каталогу (раньше на «привет» бот отвечал списком ниш и выглядел
  бездушно). История последних реплик лежит в записи партнёра, чистится
  `/reset`. Тон и границы — `TONE_RULES` в `partner-training.ts`: на «вы»,
  тепло, редкая шутка над ситуацией, без панибратства, без иронии над
  партнёром и без заумных слов.
- Доступ выдаётся личными одноразовыми приглашениями: владелец (id из
  `TELEGRAM_OWNER_CHAT_ID`) в самом боте вызывает `/invite Имя`, получает код и
  ссылку. Коды и привязка лежат в `partners/_invites.json`. Общий
  `PARTNER_BOT_ACCESS_CODE` остался запасным вариантом, но отзывается только
  сменой значения для всех сразу.
- **Кабинет закрыт по умолчанию.** Сначала проверка включалась, только если
  задан общий код или есть хотя бы одно приглашение, — тогда удаление кода
  вместе с блокировкой последнего партнёра открывало бота всем подряд. Теперь
  дверь закрыта всегда: войти можно по приглашению, по общему коду или будучи
  владельцем. `PARTNER_BOT_OPEN=1` снимает проверку (только для стенда).
- Отзыв приглашения помечает запись `revokedAt`, а не удаляет её: история
  сохраняется, повторный вход по коду невозможен.
- Команды владельца в боте: `/partners`, `/partner код`, `/invite`, `/invites`,
  `/block код`, `/unblock код`, `/admin`. В `PARTNER_BOT_COMMANDS` их нет
  намеренно: список команд виден всем пользователям бота.
- Блокировка ставит `status: "blocked"` и отзывает приглашение, но не трогает
  историю: переданные клиенты остаются в записи партнёра и в лидах.
- Переданные клиенты дополнительно уходят строкой в Google-таблицу владельца
  (`src/lib/sheets.ts`): POST на Apps Script, опубликованный как веб-приложение,
  переменные `SHEETS_WEBHOOK_URL` и `SHEETS_WEBHOOK_SECRET`. Сервисных аккаунтов
  Google Cloud намеренно нет. Сбой выгрузки не срывает передачу клиента: в
  сделке не проставляется `sheetSyncedAt`, а команда `/sync` досылает
  пропущенные строки без дублей. Инструкция и код скрипта — в `PARTNER_BOT.md`.
  Скрипт приписывает апостроф значениям, начинающимся с `=`, `+`, `-` или `@`:
  иначе телефон «+7…» становится формулой и в ячейке стоит `#ERROR!`. Даты
  берут пояс из `PARTNER_BOT_TIMEZONE` (по умолчанию `Asia/Yekaterinburg`).
- Прайс студии — `src/lib/partner-prices.ts`, раздел «💵 Цены» в меню и команда
  `/prices`. По каждой позиции две суммы: рекомендуемая (её партнёр называет
  клиенту) и максимальная (сложный проект с полным функционалом). Прайс уходит
  и в системный промпт AI как единственный источник цен. Вилки в карточках ниш
  — оценка рынка из исследования, а не прайс: об этом сказано прямо в карточке,
  чтобы партнёр не называл их клиенту как наши цены.
- Клиенты от партнёров попадают в общий `leads-store` с источником `partner`,
  в `sourceDetails` — id, username и код партнёра.
- Комиссия зависит от типа лида: холодный (только ФИО и контакты из заявки) и
  тёплый (проведена консультация, заполнен бриф, клиент готов продолжать).
  Тип бот спрашивает первым вопросом при передаче клиента и пишет его в
  `sourceDetails` лида вместе со ставкой. Тёплый лид без брифа сохраняется как
  холодный.
- Правило «комиссия выплачивается после того, как заказчик оплатил заказ» —
  условие компании, зашито константой `PAYOUT_RULE` в `partner-training.ts`.
- Ставки подтверждены компанией 2026-09-08: 15% за холодный лид, 30% за тёплый.
  Лежат в `DEFAULT_COMMISSION` (`partner-training.ts`), переменные
  `PARTNER_COMMISSION_COLD_PERCENT` и `PARTNER_COMMISSION_WARM_PERCENT` нужны
  только чтобы поменять их без правки кода.

## Продукты в `products/`

Отдельные от сайта вещи, которые студия продаёт. Своего стека не имеют:
чистый Python + Jinja2, на выходе статика. К сборке сайта (`bun run build`)
отношения не имеют.

- `products/ai-faq/` — **общий** FAQ-модуль: аккордеон на `<details>`, его
  стили и скрипт, генератор разметки `FAQPage` и проверки текста ответов
  (3–7 вопросов, ответ 40–120 слов, без ссылок внутри). Отдельного
  генератора страницы у продукта пока нет — модуль подключают другие
  продукты. Второй копии этой вёрстки в репозитории быть не должно.
- `products/neuro-portfolio/` — генератор сайтов-портфолио:
  `python generate.py client.json dist/`. Данные клиента — один JSON,
  проверяется по `schema/client.schema.json` своим валидатором
  (`validation.py`): сообщения на русском, с указанием кейса и поля, без
  трейсбеков. Четыре темы различаются **только** CSS-переменными, вёрстка
  одна — `themes/base.css`. Собранная страница не делает ни одного внешнего
  запроса: шрифты системные, иконки инлайновые, форма заявки открывает почту
  или Telegram без бэкенда.
- Критерии приёмки прогоняются: `cd products/neuro-portfolio && python selftest.py`
  (42 проверки: сборка, темы, битые данные, совпадение разметки с видимым
  текстом, контраст, вес).
- Lighthouse на примере — Performance 99–100, Accessibility 100 на всех
  темах. `validator.schema.org` из этого окружения недоступен (прокси
  отдаёт 403), разметку проверяйте руками при выкладке.
- ТЗ на нейро-портфолио ссылалось на готовый `products/ai-faq/`, но в
  репозитории его не было: FAQ-модуль создан вместе с генератором.
