# Партнёрский Telegram-бот AI-Profigrup

Кабинет партнёра: обучение, каталог 42 ниш, скрипты, возражения и передача
клиентов в студию. Живёт внутри этого же приложения — отдельный сервис
разворачивать не нужно, вебхук висит на `/api/telegram/partner`.

**Бот: [@AIProfigrupPartner_bot](https://t.me/AIProfigrupPartner_bot).** Ссылка,
которую вы даёте партнёру, вместе с кодом доступа из `PARTNER_BOT_ACCESS_CODE`.
Можно сразу с кодом в ссылке, тогда кабинет откроется без ввода:
`https://t.me/AIProfigrupPartner_bot?start=<код доступа>`.

## Что видит партнёр

| Раздел | Что там |
| --- | --- |
| 🎓 Обучение | 8 уроков по порядку, прогресс сохраняется |
| 📚 Каталог ниш | 7 блоков, 42 ниши: боль, продукт, оффер, вилка цены, готовая фраза для первого сообщения |
| 💬 Скрипты | первое касание, напоминание, короткая презентация, передача клиента |
| 🛡 Возражения | 7 разобранных ответов |
| 📝 Передать клиента | выбор типа лида, затем 2 вопроса для холодного или 3 для тёплого → заявка уходит владельцу и в базу с меткой партнёра и ставкой |
| 🤖 Спросить AI | вопрос в свободной форме; то же самое даёт любое сообщение без команды |
| 🔎 Найти нишу | поиск по слову: «стоматология», «доставка», «ремонт» |
| 💰 Условия | две ставки комиссии и правило выплаты |
| 👤 Мой профиль | код партнёра, прогресс обучения, переданные клиенты |

Команды: `/menu`, `/learn`, `/catalog`, `/deal`, `/ask вопрос`, `/find слово`,
`/me`, `/terms`, `/help`, `/cancel`, `/reset`.

**Разговор.** Любое сообщение без команды уходит наставнику «Макс», а не в
поиск по каталогу: бот отвечает по-человечески, помнит последние реплики и
держит тон из `TONE_RULES` (`src/lib/partner-training.ts`) — дружелюбно, на
«вы», с редкой уместной шуткой, без панибратства и без снисходительности.
Историю разговора очищает `/reset`. Если сообщение короткое и точно совпадает
с нишей («стоматология», «доставка еды»), под ответом появляются кнопки этих
ниш.

## Запуск за 5 шагов

1. **Создать бота.** Сделано: `@AIProfigrupPartner_bot`, создан через
   [@BotFather](https://t.me/BotFather) командой `/newbot`. Токен оттуда идёт в
   `TELEGRAM_PARTNER_BOT_TOKEN`. Если переменную не задать, партнёрский кабинет
   поднимется на основном боте, который принимает заявки с сайта.

2. **Придумать секрет вебхука.** Любая длинная случайная строка, например:
   `openssl rand -hex 24`.

3. **Прописать переменные окружения** в панели Timeweb Cloud Apps (раздел
   Environment variables) и передеплоить:

   ```
   TELEGRAM_PARTNER_BOT_TOKEN=<токен из BotFather>
   TELEGRAM_PARTNER_WEBHOOK_SECRET=<секрет из шага 2>
   PARTNER_BOT_ACCESS_CODE=<общий код; можно не задавать, если выдавать личные приглашения>
   PARTNER_MANAGER_CONTACT=@ваш_телеграм
   SITE_BASE_URL=https://aiprofigrup.ru
   ```

   Уже должны быть заданы (используются и сайтом): `TELEGRAM_OWNER_CHAT_ID` —
   куда падают заявки, `S3_*` — где хранятся партнёры и лиды, `KIE_API_KEY` —
   для кнопки «Спросить AI».

4. **Проверить связь.** Открыть в браузере:

   ```
   https://aiprofigrup.ru/api/telegram/partner?secret=<секрет>&action=ping
   ```

   В `apiHost` должен быть адрес релея, а не `api.telegram.org`, в `polling`
   — `"running": true`. Вебхук ставить не нужно: бот сам забирает сообщения
   опросом, см. раздел ниже.

5. **Проверить.** Открыть [@AIProfigrupPartner_bot](https://t.me/AIProfigrupPartner_bot),
   отправить `/start`, ввести код доступа, пройти первый урок и передать
   тестового клиента: уведомление должно прийти вам в Telegram.

## Как это устроено

| Файл | Зачем |
| --- | --- |
| `src/routes/api/telegram/partner.ts` | вебхук: проверка секрета, приём апдейтов, установка вебхука |
| `src/lib/partner-bot.ts` | вся логика: меню, экраны, состояния, передача клиента, AI |
| `src/lib/partner-catalog.ts` | данные каталога: 42 ниши, 7 блоков, фильтр выбора |
| `src/lib/partner-training.ts` | тексты: уроки, скрипты, возражения, условия |
| `src/lib/partners-store.ts` | партнёры в S3 (`partners/<telegramId>.json`) |
| `src/lib/telegram.ts` | общий клиент Telegram Bot API для обоих ботов |

Заявки от партнёров попадают в то же хранилище, что и заявки с сайта
(`leads-store`), с источником `partner`, а в `sourceDetails` лежат id, username
и код партнёра — по ним видно, кто привёл клиента.

## Что важно знать

- **Секрет обязателен.** Без `TELEGRAM_PARTNER_WEBHOOK_SECRET` роут отвечает
  503: открытый вебхук позволил бы кому угодно присылать апдейты от имени
  чужого партнёра.
- **Уведомление о клиенте** отправляется основным ботом (`TELEGRAM_BOT_TOKEN`),
  потому что с ним владелец уже переписывался. Если основного токена нет,
  пробуется партнёрский — но тогда владелец должен сам нажать `/start` в
  партнёрском боте, иначе Telegram запретит отправку.
- **Без `S3_*`** бот работает, но прогресс обучения и список партнёров живут в
  памяти процесса и теряются при рестарте. Заявки в этом режиме не сохраняются
  в базу, а только уходят уведомлением.
- **Комиссия зависит от типа лида.** Холодный: есть только ФИО и контакты из
  заявки на продукт. Тёплый: проведена первичная консультация, заполнен бриф,
  клиент готов продолжать диалог. Бот спрашивает тип первым вопросом, пишет его
  в заявку и в уведомление. Тёплый лид, отправленный без брифа, уходит как
  холодный, и партнёр об этом предупреждён.
- **Выплата только после оплаты заказа заказчиком.** Это правило зашито в коде
  (`PAYOUT_RULE` в `src/lib/partner-training.ts`) и повторяется партнёру при
  каждой передаче клиента.
- **Действующие ставки: 15% за холодный лид и 30% за тёплый.** Они зашиты в
  `src/lib/partner-training.ts`. Если ставки изменятся, их можно переопределить
  переменными `PARTNER_COMMISSION_COLD_PERCENT` и
  `PARTNER_COMMISSION_WARM_PERCENT` без правки кода.
- **api.telegram.org недоступен с прод-IP Timeweb напрямую** — трафик идёт через
  релей из `TELEGRAM_API_BASE` (см. `CLAUDE.md`). Это касается и партнёрского
  бота: если релей лёг, бот замолчит.

## Как выдавать и отзывать доступ

Управление живёт в самом боте и доступно только владельцу — тому, чей id
указан в `TELEGRAM_OWNER_CHAT_ID`. Отдельная админка не нужна, все команды
работают в личном чате с ботом.

| Команда | Что делает |
| --- | --- |
| `/invite Иван Петров` | создаёт личное одноразовое приглашение и готовую ссылку для пересылки |
| `/invites` | показывает приглашения, которыми ещё не воспользовались |
| `/partners` | список партнёров: статус, прогресс обучения, сколько клиентов передано |
| `/partner код` | карточка партнёра со всеми переданными клиентами и датами |
| `/block код` | закрывает доступ и отзывает приглашение; история сохраняется |
| `/unblock код` | возвращает доступ |
| `/admin` | эта же подсказка внутри бота |

Вместо кода партнёра в командах можно указать его `@username` или числовой id.

**Как это устроено.** Каждому партнёру выдаётся своё приглашение, а не общий
пароль: тогда доступ снимается у одного человека, не задевая остальных.
Приглашение одноразовое и закрепляется за тем, кто вошёл по нему первым.
После входа партнёр получает собственный код вида `AP-XXXX` — он попадает в
каждую переданную заявку, поэтому всегда видно, кто привёл клиента.

**История продаж** ведётся по каждому партнёру отдельно: список переданных
клиентов с датой, типом лида и ставкой лежит в его записи (`partners/<id>.json`
в S3) и показывается в `/partner код`. Сами заявки дополнительно попадают в
общее хранилище лидов с меткой партнёра. Блокировка ничего не удаляет:
заблокированный партнёр просто не может пользоваться ботом.

**Кабинет закрыт по умолчанию.** Никакой переменной для этого не нужно: без
приглашения, без общего кода и не будучи владельцем, в бот не попасть. Владелец
(id из `TELEGRAM_OWNER_CHAT_ID`) входит всегда — иначе выписывать приглашения
было бы некому. Снять проверку целиком можно переменной `PARTNER_BOT_OPEN=1`,
но это только для тестового стенда.

**Общий код** `PARTNER_BOT_ACCESS_CODE` остался как запасной вариант: он
работает для всех сразу и отзывается только сменой значения переменной. Раздав
личные приглашения, переменную можно удалить и новую взамен не заводить.

**Отозванные приглашения не удаляются**, а помечаются: по записи видно, кого и
когда приглашали, а войти по такой ссылке уже нельзя.

## Как бот получает сообщения

Опросом, а не вебхуком. Причина в том, что связь с Telegram односторонняя:
исходящие запросы уходят через релей `TELEGRAM_API_BASE`, а входящие не
доходят. Проверено вживую 2026-09-08: вебхук вставал успешно, но
`getWebhookInfo` показывал `"last_error_message": "Connection timed out"` и
растущий `pending_update_count`, в логах приложения при этом не было ни одного
запроса. Telegram не может открыть соединение к российскому IP.

Поэтому цикл `getUpdates` живёт в процессе сервера: `src/lib/partner-bot-polling.ts`,
запускается из `src/server.ts` при старте. Что важно помнить:

- Опрос и вебхук взаимоисключающи. Цикл сам снимает вебхук перед первым
  запросом, поэтому `action=set` включать не нужно.
- Один процесс на бота. Если приложение отмасштабировать на два инстанса,
  Telegram начнёт отвечать 409 — цикл переживёт это (ждёт и пробует снова),
  но сообщения будут разбираться вразнобой.
- Выключается переменной `PARTNER_BOT_POLLING=off`. Пригодится, если однажды
  входящий канал откроется и захочется вернуться на вебхук.
- Состояние цикла видно в `action=ping`, поле `polling`: запущен ли, сколько
  апдейтов обработано, последняя ошибка.

## Почему бот молчит сразу после передеплоя

Полминуты тишины после выкатки — это нормально и лечится само. Timeweb гасит
старый контейнер только после того, как новый стал здоровым, поэтому обе копии
недолго живут одновременно. Telegram разрешает опрашивать бота лишь одной из
них, второй отвечает:

```
Conflict: terminated by other getUpdates request; make sure that only one bot instance is running
```

Опрос это переживает: ждёт пять секунд и пробует снова, а при остановке
сервера сам прерывает висящий запрос по SIGTERM, чтобы не мешать новой копии.
Убедиться, что всё вернулось в норму, можно по `action=ping`: поле
`polling.lastError` должно быть `null`, а `startedAt` перестать меняться при
повторных запросах.

Если конфликт держится долго и `startedAt` скачет каждые несколько секунд —
значит приложение и правда перезапускается по кругу или запущено в двух
экземплярах. Тогда смотреть надо в логи деплоя, а не в бота.

## Если Telegram недоступен с сервера

С боевого IP Timeweb (зона РУ) `api.telegram.org` закрыт. Симптом: любой вызов
Telegram падает с `Telegram API <метод>: не удалось соединиться с
api.telegram.org (...)`, бот принимает сообщения, но молчит в ответ.

Проверка занимает один запрос:

```
https://aiprofigrup.ru/api/telegram/partner?secret=<секрет>&action=ping
```

Если в ответе `"apiHost": "api.telegram.org"`, релей не подключён: переменная
`TELEGRAM_API_BASE` пустая или отсутствует. Значение должно быть адресом
прокси-релея без завершающего слэша, например `https://tg-relay.example.workers.dev`.
Код дописывает к нему `/bot<токен>/<метод>` сам.

Простейший релей — Cloudflare Worker, который прозрачно проксирует запрос:

```js
export default {
  async fetch(request) {
    const url = new URL(request.url);
    if (!url.pathname.startsWith("/bot")) return new Response("Not found", { status: 404 });
    return fetch(`https://api.telegram.org${url.pathname}${url.search}`, {
      method: request.method,
      headers: { "Content-Type": request.headers.get("content-type") ?? "application/json" },
      body: request.method === "POST" ? await request.arrayBuffer() : undefined,
    });
  },
};
```

Отдельная авторизация ему не нужна: без токена бота в пути релей бесполезен, а
токен и так знает только приложение. Если Cloudflare с сервера тоже недоступен
(Роскомнадзор периодически душит его в РФ), тот же прокси поднимается на любом
VPS вне зоны РУ, хоть на nginx с `proxy_pass https://api.telegram.org;`.

Входящие апдейты через релей не идут: их Telegram сам присылает на вебхук
сайта, а вход в РФ не блокируется. Релей нужен только для исходящих ответов.
